# Audio Decode Black-Box Reference Tests

The runtime decoder must not depend on BASS. The reference tests are therefore
fixture-based: each case provides the compressed input plus a PCM reference WAV
that was generated outside this repository by an accepted oracle.

## Running

Set `OSUPLAYER_AUDIO_SYNC_FIXTURES` to a fixture directory, then run:

```powershell
$env:OSUPLAYER_AUDIO_SYNC_FIXTURES = "D:\audio-sync-fixtures"
dotnet test tests\OsuPlayer.Media.Audio.Tests\OsuPlayer.Media.Audio.Tests.csproj -c Debug --no-restore
```

If the environment variable is not set, the corpus test is skipped as a no-op.
The offset-estimator self-tests still run.

The corpus test decodes each fixture twice:

1. Decode with MP3 gapless correction disabled and report the raw offset/length
   delta against `reference.wav`.
2. Decode through the default runtime path and assert the corrected PCM is within
   the offset/correlation budgets.

## Runtime Auto-Correction

`AudioCacheManager` also has a BASS-compatible automatic MP3 gapless correction
path. It parses the MP3 Xing/Info LAME/Lavf/Lavc extension and applies a direct
PCM trim:

- skip `encoderDelay + 529` samples from the start
- discard trailing padding when the header declares padding beyond the decoder
  delay
- rescale the correction if the cached output sample rate differs from the MP3
  source sample rate

## Fixture Layout

Each case is one directory:

```text
audio-sync-fixtures/
  lame-vbr-xing/
    input.mp3
    reference.wav
    case.json
  cbr-info/
    input.mp3
    reference.wav
```

`reference.wav` must be stereo 16-bit PCM. Its sample rate is used as the target
decode sample rate.

Optional `case.json`:

```json
{
  "maxSearchMilliseconds": 250,
  "windowMilliseconds": 100,
  "allowedOffsetFrames": 24,
  "durationToleranceFrames": 96,
  "minCorrelation": 0.985
}
```

## Reference Generation

Generate `reference.wav` outside the product build from any decoder whose timing
semantics you accept as authoritative. For osu compatibility, this can be an
osu-framework/BASS harness configured with:

- decode stream, not playback stream
- prescan enabled
- `BASS_CONFIG_MP3_OLDGAPS = 1`
- output as stereo 16-bit PCM at the target sample rate

The repository does not need to reference or redistribute BASS for these tests.
Reference WAVs can also be produced from a separately installed osu build or a
private oracle tool.

## Minimum Corpus

Keep the corpus small enough for CI but broad enough to cover MP3 timing traps:

- LAME VBR with Xing/LAME header
- LAME CBR with Info/LAME header
- MP3 with no gapless/encoder-delay metadata
- MP3 with iTunes `iTunSMPB`
- ID3v2 tags with different sizes before the first frame
- mono and stereo sources, decoded to stereo reference WAV
- 44.1kHz and 48kHz sources
- OGG Vorbis cases as a guard for subtle resampler/decoder drift

For every regression, add the smallest audio file that reproduces it and keep
the reference WAV generated by the oracle at the moment the expectation is
accepted.
